Ocelot as a Compute Fabric

Deploy Ocelot's BitTorrent swarm as a peer-to-peer job-distribution layer — routing compute payloads, container layers, CI artifacts, and ML model shards across heterogeneous hardware without a central broker.

Dell R640 M1 Mac Mini 8 GB UC-9 Compute Shuttle Prometheus

What "Compute Fabric" Means

Ocelot's announce engine tracks which peers hold which torrent pieces in real time. When you register a payload under category = compute, the swarm becomes a self-balancing distribution mesh:

  • UC-9 Compute Shuttle — GET /compute/scale returns a scale_up verdict when the leecher/seeder ratio exceeds 4, so your orchestrator knows when to spin extra workers.
  • UC-11 Container Layer Cache — container image layers are content-addressed torrents; peers pull only the missing diff, identical to Docker's layer model but without a registry bottleneck.
  • UC-18 CI Artifact Store — build artefacts (binaries, test reports, coverage data) are registered with a TTL; Ocelot garbage-collects them after ci_artifact_ttl seconds.
  • UC-20 Edge Rollout — staged rollouts advance automatically when the anomaly rate stays below rollout_anomaly_gate, giving you canary deployments with zero extra tooling.
Private tracker precondition

All peers must present a valid passkey. Run Ocelot behind a firewall; set a strong site_password and jwt_secret before exposing the Admin API. The compute fabric is only as secure as your passkey issuance process.

Prerequisites

Dell PowerEdge R640
  • • RHEL / Rocky / Ubuntu 22.04 LTS (x86_64)
  • • Go 1.21+ — dnf install golang or tarball from go.dev/dl
  • • gcc + sqlite-devel for CGo SQLite: dnf install gcc sqlite-devel
  • • Redis 7 (optional, for dual-write): dnf install redis
  • • systemd (pre-installed)
  • • Port 6969/tcp open (or your chosen listen_port)
  • • Port 8181/tcp for Admin API (firewall to mgmt VLAN only)
Apple M1 Mac Mini 8 GB
  • • macOS 13 Ventura or 14 Sonoma (arm64)
  • • Xcode Command Line Tools: xcode-select --install
  • • Go 1.21+ arm64 tarball from go.dev/dl
  • • Homebrew SQLite headers: brew install sqlite
  • • No Redis required (skip for RAM-constrained profile)
  • • Allow ocelot in System Settings → Privacy → Local Network
  • • Open port 6969 in macOS pf firewall if needed

Build from Source 

# 1 — clone
git clone https://github.com/mgdavisxvs/Ocelot.git
cd Ocelot

# 2 — build (CGo required for mattn/go-sqlite3)
CGO_ENABLED=1 go build -ldflags="-s -w" -o ocelot .

# 3 — verify
./ocelot --version || ./ocelot -h

# 4 — install
sudo install -m 0755 ocelot /usr/local/bin/ocelot

# 5 — create runtime directories
sudo mkdir -p /var/lib/ocelot/db
sudo mkdir -p /etc/ocelot
sudo useradd -r -s /sbin/nologin ocelot
sudo chown -R ocelot:ocelot /var/lib/ocelot
# 1 — ensure arm64 Go is active
go env GOARCH        # should print: arm64

# 2 — point CGo at Homebrew SQLite headers
export CGO_CFLAGS="-I$(brew --prefix sqlite)/include"
export CGO_LDFLAGS="-L$(brew --prefix sqlite)/lib"

# 3 — clone + build
git clone https://github.com/mgdavisxvs/Ocelot.git
cd Ocelot
CGO_ENABLED=1 go build -ldflags="-s -w" -o ocelot .

# 4 — install (no root needed for personal machine)
mkdir -p ~/opt/ocelot/db ~/opt/ocelot/conf
cp ocelot ~/opt/ocelot/

# 5 — smoke test
~/opt/ocelot/ocelot -c /dev/null &   # starts with defaults
curl -s http://localhost:34000/stats
kill %1

Memory budget: with max_middlemen=15000 and batch_buffer_cap=2048, steady-state RSS is ~180–220 MB, leaving ~7.5 GB for macOS, your workload, and the SQLite page cache. If RSS climbs past 400 MB, reduce max_middlemen to 8000.

Service Setup & Lifecycle

/etc/systemd/system/ocelot.service 
[Unit]
Description=Ocelot BitTorrent Tracker — Compute Fabric
After=network-online.target redis.service
Wants=network-online.target

[Service]
Type=simple
User=ocelot
Group=ocelot
ExecStart=/usr/local/bin/ocelot -c /etc/ocelot/ocelot.conf
ExecReload=/bin/kill -HUP $MAINPID
ExecStop=/bin/kill -TERM $MAINPID

WorkingDirectory=/var/lib/ocelot
RuntimeDirectory=ocelot
StateDirectory=ocelot

# Graceful drain timeout — allow in-flight announces to complete
TimeoutStopSec=60

# Resource limits
LimitNOFILE=131072
LimitNPROC=32768

# Hardening
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/var/lib/ocelot
CapabilityBoundingSet=

Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
# Enable + start
sudo systemctl daemon-reload
sudo systemctl enable --now ocelot

# Reload config (SIGHUP — no restart needed)
sudo systemctl reload ocelot

# Reload in-memory torrent/user state (SIGUSR1)
sudo kill -USR1 $(systemctl show ocelot --value -p MainPID)

# Logs
sudo journalctl -u ocelot -f

# Status
sudo systemctl status ocelot

Compute Fabric API

All Admin API calls require Authorization: Bearer <JWT>. Obtain a token from your Gazelle site or issue one directly against POST /admin/token with your jwt_secret.

POST /admin/token Issue a JWT 
curl -s -X POST http://localhost:8181/admin/token \
  -H 'Content-Type: application/json' \
  -d '{"secret":"YOUR_JWT_SECRET"}' | jq .

# Response
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}

export OCELOT_TOKEN="eyJ..."
GET /compute/scale UC-9: Scale-up verdict

Returns scale_up: true when the swarm leecher/seeder ratio exceeds 4.0, indicating demand is outpacing supply — your orchestrator should launch additional worker peers. 

curl -s http://localhost:8181/compute/scale \
  -H "Authorization: Bearer $OCELOT_TOKEN"

# Response when demand is high
{
  "scale_up": true,
  "ratio": 6.2,
  "seeders": 12,
  "leechers": 74
}

# Response when supply is adequate
{
  "scale_up": false,
  "ratio": 1.8,
  "seeders": 44,
  "leechers": 80
}

Orchestrator integration pattern: poll every 30 s; on scale_up: true, launch ceil(ratio / 4) - 1 additional seeder nodes targeting the highest-demand torrent hash.

GET /compute/eta UC-9: Job completion estimate 
curl -s "http://localhost:8181/compute/eta?info_hash=TORRENT_HEX_HASH" \
  -H "Authorization: Bearer $OCELOT_TOKEN"

# Response
{
  "info_hash": "abc123...",
  "eta_seconds": 42,
  "pieces_remaining": 17,
  "active_peers": 8
}
POST /ci/artifact/register UC-18: Register a CI artefact 
curl -s -X POST http://localhost:8181/ci/artifact/register \
  -H "Authorization: Bearer $OCELOT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "info_hash":  "deadbeef...",
    "pipeline_id": "build-42",
    "branch":     "main",
    "ttl":        86400
  }'
POST /container/layer UC-11: Register a container layer 
curl -s -X POST http://localhost:8181/container/layer \
  -H "Authorization: Bearer $OCELOT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "info_hash":  "sha256:abc...",
    "image_ref":  "myapp:latest",
    "layer_digest": "sha256:def..."
  }'
POST /edge/rollout/start UC-20: Begin staged rollout 
# Starts a 5-stage rollout: 5% → 20% → 50% → 80% → 100%
curl -s -X POST http://localhost:8181/edge/rollout/start \
  -H "Authorization: Bearer $OCELOT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{
    "info_hash": "deadbeef...",
    "stages":    [5, 20, 50, 80, 100],
    "dwell_sec": 120
  }'

# Check rollout status
curl -s "http://localhost:8181/edge/rollout/status?info_hash=deadbeef..." \
  -H "Authorization: Bearer $OCELOT_TOKEN"

Log pattern quick-reference

Log fragmentMeaning
circuit breaker: state=openSQLite write failures exceeded threshold; DB overloaded
SLA alert: no announceA compute peer missed its SLA window — check network
preservation alert: replicas=1Torrent is underseededed; risk of data loss
anomaly detectedPeer sent anomalous traffic; may indicate cheating client
rollout advancedEdge rollout moved to next stage automatically
peer snapshot savedSwarm state persisted; fast restart possible
